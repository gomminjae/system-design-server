# 통스통스 (TongsTongs)

> 유저가 채워가는 미니앱들의 땅 — 큐레이션형 웹 미니앱 플랫폼

심리테스트·유형검사로 시작해서, 운세·미니게임·도구까지 확장되는 **종합 미니앱 플랫폼**.
유저가 미니앱을 제출하면 내가 심사해서 공개하고, 다른 유저들이 즐긴다.

## 한눈에 보는 구조

```
┌─────────────────────────────────────┐
│ 호스트 앱 (React Native)              │  ← 범용. 미니앱 타입 안 가림
│   - 카탈로그/디스커버리 화면           │
│   - WebView 미니앱 런타임 (= 샌드박스)  │
│   - 결과 공유 (바이럴 엔진)            │
├─────────────────────────────────────┤
│ 미니앱 계약 (Manifest + 메시지 규약)    │  ← 확장성의 심장
├─────────────────────────────────────┤
│ 미니앱 (웹, 유저 제작)                 │  ← type:"quiz" 먼저 → game/tool 확장
├─────────────────────────────────────┤
│ 운영 백엔드 (BaaS)                     │  ← 카탈로그 API + 번들 호스팅 + 심사 + kill switch
└─────────────────────────────────────┘
```

## 핵심 설계 원칙

1. **미니앱 = 순수 웹.** 호스트는 RN, 미니앱은 웹(HTML/JS). 런타임 배포(앱 재심사 없이 미니앱 추가)는 웹만 가능.
2. **타입을 하드코딩하지 않는다.** "테스트"는 미니앱의 첫 번째 종류일 뿐. 범용 매니페스트로 설계해 game/tool 확장 시 호스트 안 고침.
3. **번들은 내가 호스팅** (모델 A). 버전 박힌 URL + CSP로 "원격 코드 금지 / 스냅샷 고정" 강제.
4. **샌드박스 = 온디바이스 WebView.** 서버는 격리를 돌리는 게 아니라 배포·통제만 한다.
5. **자기완결형만 받는다.** 답→결과로 끝나는 콘텐츠만. 유저↔유저 연결(소개팅)·실거래는 안 받음.

## 애플 심사 (4.7) 가드레일

- ✅ 웹 미니앱 호스팅은 4.7이 허용하는 합법 카테고리
- ❌ 미니앱에 네이티브 API(카메라/결제/위치) 브리지 노출 금지 (4.7.2)
- ❌ 미니앱 내 디지털 상품은 외부결제 금지 → 애플 IAP 필수
- ✅ 미니앱 인덱스/매니페스트를 애플에 신고 (4.7.4)
- ✅ 연령등급·콘텐츠 가이드 미니앱별 준수

## 개발 로드맵

| Phase | 내용 | 검증/목표 |
|---|---|---|
| **0** | 설계 (매니페스트·카탈로그·메시지·카테고리 정책) | 종이 위, 코드 0 |
| **1** | RN + WebView 런타임 관통 (하드코딩 테스트 1개) | "런타임 되나?" |
| **2** | 애플 심사 조기 제출 (얇은 슬라이스) | "애플 승인되나?" |
| **3** | 서버화 (카탈로그 API + 번들 CDN + kill switch) | 여러 테스트 |
| **4** | 결과 공유 (바이럴 엔진) | 유저 획득 |
| **5** | 심사 백오피스 | 제출→승인→배포 |
| **6** | 코딩 없는 제작 템플릿 (UGC 폭발) → 정식 런칭 | 콘텐츠 자가증식 |
| **V2+** | 운세 IAP → 창작자 수익 → 미니게임 → 도구 → 외부 개발자 오픈 | 슈퍼앱 확장 |

자세한 설계는 [`docs/PHASE0-DESIGN.md`](docs/PHASE0-DESIGN.md) 참고.
