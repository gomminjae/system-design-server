# 퍼스널 디자인 설계 (초안)

**작성일**: 2026-06-30
**상태**: 초안 v0.1 — 결정·추진용
**한 줄**: 자기발견/운세 서비스를 "나에 대한 것"으로 느끼게 만드는 개인화를, 수작업 없이 SDUI resolver로 확장 가능하게.
**용어**: 콘텐츠 유닛 = tong(코드 용어). 사용자 노출 별도명 없음. 서비스 브랜드 = Cosmi. 관계 문서: [`business-case.md`], [`branding.md`], 원칙 [[sdui-dynamic-binding-over-flags]].

## 0. 결정 (먼저)

1. **퍼스널의 정의 = "누적되는 나의 프로필(페르소나)".** 푼 통 결과들이 하나의 자기 초상으로 쌓인다. 이게 퍼스널·리텐션·공유·개인화의 단일 축.
2. **확장성 = per-user SDUI resolve.** 개인화는 플래그/수동 편성이 아니라 resolver가 유저 컨텍스트로 계산. 코드 한 벌로 N명.
3. **토대 3개 선행**: ① 유저 식별(Supabase Auth, 익명→로그인) ② 이벤트/결과 추적 ③ resolver의 유저 컨텍스트 확장. (①②는 수익화와 공유의 공통 토대 = 중복 투자 아님)
4. **순서**: 인증 → 결과 저장/프로필 → 개인화 피드 → 프로필 공유 → 퍼스널 비주얼 → 데일리(앱).

---

## 1. 왜 "프로필"이 핵심인가

| 효과 | 설명 |
|---|---|
| 퍼스널 | 일반 퀴즈 모음 → *내 정체성*. 앱이 나에 대한 것이 됨 |
| 리텐션 | 프로필을 채우려 재방문 |
| 바이럴 | "내 프로필 카드" 공유 → K-factor |
| 개인화 연료 | 프로필 기반 추천·맞춤 피드 |
| 확장성 | 결과 저장 + 데이터 렌더뿐 — 수작업 0, 통 늘수록 풍부 |

시장 검증: Co-Star/The Pattern(생일 1회→평생 개인화), Nebula/포스텔러(사주·타로 프로필 누적), Finch/BeReal(누적 기록=재방문). 공통 원리 = *초기 신호 1회 + 누적 프로필 + "내 것"으로 보이는 콘텐츠*.

---

## 2. 데이터 모델 (스케치)

```
user_profile        user_id PK, birth_dt?, gender?, interests[], market, theme/aura?, updated_at
tong_result          id, user_id, tong_id, result_key, result_data(JSON), created_at
event               id, user_id?, type(view|start|complete|share|unlock), tong_id?, props(JSON), ts
```
- `tong_result` = 프로필의 원천(누적 결과).
- `event` = 개인화·추천·수익화·세일즈 공통 인프라.
- 익명 유저: device 기반 임시 user_id → 로그인 시 병합(merge).

---

## 3. 확장 가능한 개인화 아키텍처

```
유저 컨텍스트(profile + tong_result 이력 + market + 시각)
        │
   ScreenResolver (per-user 확장)
        │
  개인화 섹션: "당신을 위한 통" · "OOO님의 오늘 운세" · "프로필 이어가기"
```
- 현재 resolver는 market까지 받음 → **user 컨텍스트 추가**가 자연스러운 다음 단계.
- 규칙은 데이터 기반(이력 카테고리 가중치, 미완 프로필 슬롯 추천) — 수동 편성 금지.
- 캐시: 개인화 섹션은 per-user라 스크린 캐시 키에 user 차원 추가 또는 개인화 섹션만 비캐시.

## 4. 기능 사다리 (싼 것 → 풍부한 것)

| # | 기능 | 가치 | 전제 |
|---|---|---|---|
| 1 | **온보딩 신호 1회**(생일/관심) | 첫날부터 맞춤 운세·추천 | profile |
| 2 | **결과 히스토리 + 나의 프로필** | 퍼스널 핵심·리텐션 | 인증 + tong_result |
| 3 | **개인화 홈**(resolver) | "당신을 위한" 피드 | 이력 + resolver |
| 4 | **프로필 공유 카드**(OG) | 바이럴 | /share OG |
| 5 | **퍼스널 비주얼**(아우라 컬러·아바타) | 디자인적 퍼스널 | 결과 매핑 |
| 6 | **데일리 개인화 푸시** | 재방문 | 앱(네이티브) |

---

## 5. 디자인(비주얼) 측면의 "퍼스널"

- 결과가 *내 색/내 카드*로 보이게: 결과별 컬러·이모지·뱃지 → 프로필에 누적되며 **나만의 팔레트** 형성("아우라 컬러").
- 프로필 = 수집형(컬렉션 채우기) UX → 빈 슬롯이 다음 통 유도(자연스러운 추천).
- 통일감: 통 표준 템플릿의 theme 토큰을 프로필과 공유 → 앱·통·프로필이 한 결.

---

## 6. 전제 / 리스크

- **인증이 게이트**: 프로필 누적은 유저 식별 필요 → Supabase Auth(익명→업그레이드). 결제와 동일 선행.
- **이벤트 추적 우선 인프라**: 개인화·추천·공유·수익화·세일즈 전부 의존 → 가장 먼저 깔 가치.
- 개인화 캐시 복잡도 ↑ → 개인화 섹션 범위를 작게 시작(홈 상단 1~2개 섹션만 per-user).

## 7. 추진 (다음 액션)

1. **이벤트 추적 + tong_result 저장** 스키마/엔드포인트 (개인화·수익화 공통 토대)
2. **온보딩 신호**(생일/관심) → profile
3. **나의 프로필 페이지**(누적 결과 렌더) + 공유 카드
4. resolver **user 컨텍스트 확장** → 개인화 홈 섹션 1~2개
> 1·2가 가장 저렴하고 파급 큼. 인증(Supabase Auth) 위에 올라감.
